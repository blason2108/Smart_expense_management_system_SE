# Contributing

Thank you for contributing to the Smart Expense & Budget Management project.

## Workflow

1. Sync your local `main` branch with the repository's latest `main`.
2. Create a focused branch for one issue or change.
3. Keep changes limited to the task and avoid committing generated files, local databases, credentials, or environment files.
4. Run the checks relevant to your change before opening a pull request.
5. Open a pull request against the team's `main` branch and describe the change, the reason for it, and the validation performed.

## Code and review expectations

- Follow the conventions already used in the affected part of the project.
- Prefer small, reviewable commits with clear messages.
- Add or update tests when behavior changes.
- Update documentation when setup steps, configuration, or user-visible behavior changes.
- Do not include secrets, access tokens, personal data, or production data in commits.

## Pull request checklist

- [ ] The change addresses the intended issue.
- [ ] Relevant tests and checks have been run.
- [ ] No unrelated files or generated artifacts are included.
- [ ] Documentation is updated where needed.
- [ ] The pull request explains the change and how it was validated.
